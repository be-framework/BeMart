## 要約

- **未実装の画面・ルートはゼロ。本物のギャップもゼロ。** 248項目すべて実装が存在する。
- 管理 99 リソース全てがルート解決（404 は1つも無い）。65 画面が認証後に実描画。残りは POST 専用操作（20）/パラメータ必須（6）/CSV ダウンロード（7、headless では abort するが実在）/内部ディスパッチ `action-redirect`（1、画面ではない）。
- EF03 複数配送（当初唯一の候補）も実装済と確認。
- 🟢（管理の大半）は「実装・画面描画は確認済、各操作の end-to-end 検証は深掘り中」の意味。front 購入フローのように管理操作も実操作で詰めるのが次段。
- 注: EC-CUBE の JS バンドルは移植対象外のため、`data-path`/`data-trigger` 等の JS トリガ要素は no-JS ハーネスでは「クリック」では発火しない（対応ルートへ直接 goto すれば到達）。これは未実装ではなく移植スコープ上の特性。

## 既知の技術的負債（実装の穴ではないが要修正）

- `AddCartItemInput::$sessionPrefix = 'session-prefix-1'` — セッション識別子のハードコード既定（DI/Resource 注入の取りこぼし）。Resource が実セッションごとに override していなければカート混線のリスク。要確認・要修正。
